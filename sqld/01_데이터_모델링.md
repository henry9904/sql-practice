# 01. 데이터 모델링의 이해

## 데이터 모델링이란

현실 세계의 데이터를 추상화하여 DB 구조로 표현하는 과정.

3단계: **개념적** → **논리적** → **물리적**

| 단계 | 산출물 | 특징 |
|---|---|---|
| 개념적 | ERD (개략) | 엔티티와 관계만, DB 독립적 |
| 논리적 | ERD (상세) | 속성/키/관계 정의, 정규화 적용 |
| 물리적 | 테이블 DDL | DBMS 종속, 인덱스/파티션 포함 |

---

## 엔티티 (Entity)

> 저장할 가치가 있는 정보의 집합. 테이블에 해당.

조건:
- 인스턴스(행)가 2개 이상
- 속성이 1개 이상
- 다른 엔티티와 관계가 있어야 함

종류:
- **유형**: 물리적으로 존재 (고객, 상품)
- **개념**: 눈에 안 보임 (부서, 계좌)
- **사건**: 행위 결과 (주문, 로그)

---

## 속성 (Attribute)

> 엔티티의 특성. 컬럼에 해당.

종류:
- **기본**: 업무적으로 의미 있는 속성 (이름, 금액)
- **설계**: PK처럼 설계 시 추가 (주문번호)
- **파생**: 계산으로 나오는 값 (나이 ← 생년월일)

---

## 관계 (Relationship)

표기: ERD에서 선으로 연결

카디널리티:
- 1:1
- 1:N (가장 흔함)
- M:N → 중간 테이블로 분해

참여도:
- 필수 참여: `|` (모든 행이 관계 있어야 함)
- 선택 참여: `O` (없어도 됨)

---

## 식별자 (Identifier)

| 구분 | 설명 |
|---|---|
| 주식별자 | PK. 유일성 + NOT NULL |
| 보조식별자 | UNIQUE지만 PK 아님 |
| 외부식별자 | FK. 다른 엔티티 참조 |
| 복합식별자 | PK가 2개 이상 컬럼 조합 |

식별 관계 vs 비식별 관계:
- **식별**: 부모 PK가 자식 PK에 포함됨
- **비식별**: 부모 PK가 자식 FK지만 PK는 아님

---

## 시험 포인트

- 모델링 3단계 순서 암기
- 엔티티 성립 조건 (인스턴스 2개 이상 등)
- 식별 관계 vs 비식별 관계 구분
- 카디널리티 M:N → 중간 테이블 변환
